# Product Decisions

## 1. Чистый стек (Vanilla HTML/CSS/JS)
- **Решение**: Отказ от React, Vue или jQuery в пользу чистого JavaScript (ES6+).
- **Обоснование**: Требование технического задания («JavaScript-логика должна быть написана самостоятельно»), нулевые накладные расходы на сборку, мгновенная загрузка в любом браузере и максимальная прозрачность кода для проверки.

## 2. Структура проекта (двойное размещение в project/ и корне)
- **Решение**: Исходные файлы проекта размещены в `project/` (`project/index.html`, `project/style.css`, `project/script.js`), а также продублирован корневой `index.html`.
- **Обоснование**: Полное соблюдение ТЗ («project/ ├── index.html ├── style.css └── script.js») и одновременное удобство запуска прямо из корня репозитория.

## 3. Делегирование событий (Event Delegation)
- **Решение**: Обработка кликов по кнопкам «Выполнить», «Редактировать» и «Удалить» через общий слушатель на контейнере списка `#tasks-list`.
- **Обоснование**: Высокая производительность при динамическом добавлении и фильтрации задач без необходимости перенавешивания обработчиков.

## 4. Контекстный калькулятор дедлайнов
- **Решение**: Вместо вывода сухой даты добавлен расчет оставшихся дней («Осталось 3 дня», «Сегодня дедлайн!», «Просрочено на 2 дня»).
- **Обоснование**: Критически важная функция для студентов, позволяющая визуально приоритизировать задачи без ручного подсчета дней в календаре.

## 5. Предустановленные учебные демо-задачи
- **Решение**: Если `localStorage` пуст при первом открытии, загружаются 4 реалистичных примера (коллоквиум, курсовая, лабораторная). Добавлена кнопка «Сбросить к примерам».
- **Обоснование**: Преподаватель или проверяющий сразу видит живой интерфейс, бейджи приоритетов и шкалу прогресса без необходимости вручную заполнять 5 задач перед тестированием.
