# Implementation Plan: «Менеджер учебных задач»

## Goal
Разработать и протестировать полноценное веб-приложение для управления учебными задачами студентов на чистом стеке HTML5, CSS3 и vanilla JavaScript с соблюдением требований ТЗ, качественным адаптивным UI, фильтрацией, сортировкой, статистикой и сохранением в localStorage.

## Acceptance criteria
1. Добавление задачи: форма с названием, описанием, приоритетом (низкий/средний/высокий) и сроком выполнения (валидация обязательных полей).
2. Управление задачами:
   - Чекбокс переключения статуса «выполнено / не выполнено».
   - Удаление задачи с подтверждением / уведомлением.
   - Редактирование всех полей задачи через модальное окно.
3. Фильтрация задач:
   - «Все», «Активные», «Выполненные», «С высоким приоритетом» с мгновенной фильтрацией без перезагрузки страницы.
4. Статистика:
   - Виджеты: «Всего задач», «Выполнено», «В процессе», интерактивный прогресс-бар в %.
5. Хранение данных:
   - Персистентность в `localStorage` (задачи сохраняются при перезагрузке страницы, корректно загружаются при первом открытии).
6. Дополнительный функционал:
   - Сортировка по сроку выполнения и по приоритету.
   - Полноценная адаптивность под мобильные телефоны (360px+), планшеты и десктопы.
   - Живой поиск по тексту задач.
7. Архитектура:
   - Чистый JavaScript без внешних фреймворков и библиотек.
   - Размещение исходных файлов в `project/`: `index.html`, `style.css`, `script.js` (а также корневой `index.html` для прямого запуска).

## Milestones
- **M1: Спецификация и дизайн** (Готово): Бриф, источники, дизайн-система, план.
- **M2: Каркас разметки и стили** (В работе): Семантическая структура HTML, отзывчивый CSS (variables, grid, cards, badges, modal, toast, responsive media queries).
- **M3: Модульная логика JavaScript**:
  - `storage.js` / модуль данных (CRUD, валидация схемы, дефолтные учебные задачи);
  - `render.js` / рендерер компонентов, бейджей дедлайнов и карточек задач;
  - `stats.js` / расчёт метрик и счетчиков фильтров;
  - `filters-sort.js` / фильтрация по статусам/приоритету, живой поиск и сортировка;
  - `modal.js` & `toasts.js` / управление диалогом редактирования и нотификациями.
- **M4: Размещение файлов**: Синхронизация файлов в директорию `project/` и корневой запуск.
- **M5: Тестирование и верификация (QA)**:
  - Автоматизированная проверка разметки, скрипта и стилей.
  - Проверка функционала добавления, редактирования, фильтрации, сортировки, удаления, переключения статуса и localStorage.
  - Проверка мобильного вида (viewports 375px, 768px, 1200px).
  - Проверка доступности (a11y) и производительности.
- **M6: Финализация и отчет**: Оформление документации и чек-листа сдачи.

## Risks / assumptions
- *Риск*: Повреждение или невалидный JSON в `localStorage`. *Решение*: Обернуть чтение в `try/catch` с откатом к безопасному состоянию по умолчанию.
- *Риск*: Часовые пояса при парсинге дат `YYYY-MM-DD`. *Решение*: Сравнивать даты как строковые компоненты года, месяца и дня или с обнулением локального времени, чтобы избежать смещения на 1 день назад/вперед.
- *Риск*: XSS при рендеринге пользовательского ввода в HTML. *Решение*: Обязательное экранирование строковых полей через `textContent` или функцию-санитизатор.

## Verification plan
- Smoke-тесты: проверка загрузки приложения без ошибок консоли.
- Функциональные тесты: полный цикл добавления, отметки, редактирования, поиска, фильтрации и сохранения.
- Тестирование localStorage: перезагрузка страницы и проверка сохранности состояния.
- Респонсив-тесты: стили на мобильных и десктопных разрешениях.
