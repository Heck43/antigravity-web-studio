# Release report

Read `docs/QA.md`, `docs/DESIGN.md`, `docs/SOURCES.md`, and the final diff.

Write `docs/RESULT.md` with:
- product summary;
- implementation highlights;
- research/design inputs;
- test scenarios and outcome;
- known limitations;
- how to run the app;
- files/artifacts worth reviewing.

Use “verified” only for checks actually performed.
